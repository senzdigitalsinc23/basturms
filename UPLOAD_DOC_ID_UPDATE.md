# Upload doc_id Generation Update

**Date:** February 22, 2026  
**Status:** ✅ COMPLETE  
**Endpoint:** `/api/v1/uploads`

---

## Change Summary

Updated the file upload endpoint to automatically generate `doc_id` in the format `user_id_randomstring` based on the authenticated user's `user_id`.

---

## What Changed

### Before
- `doc_id` was an optional parameter in the request body
- Users had to manually provide the `doc_id`
- Format was not standardized

### After
- `doc_id` is automatically generated by the system
- Format: `user_id_randomstring` (e.g., `user1_a3f5b2c8`)
- Based on authenticated user's `user_id` field
- No need to include `doc_id` in the request

---

## doc_id Format

**Pattern:** `{user_id}_{random_string}`

**Components:**
1. **user_id:** The authenticated user's `user_id` field from the database
2. **Separator:** Underscore (`_`)
3. **random_string:** 8-character random hexadecimal string

**Examples:**
- `USR001_91fe0d0f`
- `user1_c3533910`
- `STF123_079db670`
- `teacher_john_a23acec9`

### Request Body

**Before:**
```json
{
  "file": "<binary>",
  "doc_type": "profile_picture",
  "doc_id": "user1_12323"  // ❌ Required manual input
}
```

**After:**
```json
{
  "file": "<binary>",
  "doc_type": "profile_picture"
  // ✅ doc_id is automatically generated
}
```

### Response

The response now includes the automatically generated `doc_id`:

```json
{
  "success": true,
  "upload_id": 123,
  "url": "uploads/profile_pictures/user1_a3f5b2c8_profile_picture_91fe0d0f.jpg",
  "doc_name": "profile.jpg"
}
```

## Implementation Details

### File Modified
**Path:** `App/Controllers/Api/v1/UploadController.php`

**Method:** `upload()`

**Changes:**
```php
// Get authenticated user's user_id from session
$user = \App\Core\Session::get('user');
if (!$user || !isset($user['user_id'])) {
    throw new Exception("User not authenticated.");
}

$userId = $user['user_id']; // e.g., "USR001", "user1"

// Generate doc_id in format: user_id_randomstring
$randomString = substr(md5(uniqid(mt_rand(), true)), 0, 8);
$docId = $userId . '_' . $randomString;

// Pass to upload service
$result = $this->uploadService->upload($files['file'], $docType, $docId);
```

## Usage Examples

### cURL Example
```bash
curl -X POST "http://localhost:8000/api/v1/uploads" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -F "file=@/path/to/image.jpg" \
  -F "doc_type=profile_picture"
```

### JavaScript/Fetch Example
```javascript
const formData = new FormData();
formData.append('file', fileInput.files[0]);
formData.append('doc_type', 'profile_picture');

const response = await fetch('/api/v1/uploads', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${token}`
  },
  body: formData
});

const result = await response.json();
console.log('Upload successful:', result);
// Result includes auto-generated doc_id in the database
```

### PHP Example
```php
$ch = curl_init('http://localhost:8000/api/v1/uploads');

$file = new CURLFile('/path/to/image.jpg', 'image/jpeg', 'profile.jpg');

curl_setopt_array($ch, [
    CURLOPT_POST => true,
    CURLOPT_POSTFIELDS => [
        'file' => $file,
        'doc_type' => 'profile_picture'
    ],
    CURLOPT_HTTPHEADER => [
        'Authorization: Bearer ' . $token
    ],
    CURLOPT_RETURNTRANSFER => true
]);

$response = curl_exec($ch);
$result = json_decode($response, true);

echo "doc_id: " . $result['doc_id']; // Auto-generated
```

## Database Storage

The generated `doc_id` is stored in the `uploads` table:

```sql
INSERT INTO uploads (doc_id, doc_name, doc_type, url, file_type, file_size, uploaded_at)
VALUES ('user1_a3f5b2c8', 'profile.jpg', 'profile_picture', 'uploads/profile_pictures/...', 'image/jpeg', 12345, NOW());
```

**Query by user:**
```sql
SELECT * FROM uploads WHERE doc_id LIKE 'user1_%';
```

## Backward Compatibility

⚠️ **Breaking Change:** This is a breaking change if clients were manually providing `doc_id`.

**Migration Path:**
1. Update client applications to remove `doc_id` from upload requests
2. The system will automatically generate the correct `doc_id`
3. Old uploads with manual `doc_id` will continue to work
